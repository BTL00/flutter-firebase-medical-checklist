# 07 · Flutter client (iOS, Android, web)

The device is hostile territory: shared phones, rooted devices, screenshots, lock-screen notifications, old OS versions. Every item here is something you can verify in the repo or on a test device.

## A. Build, toolchain and reproducibility

- [ ] **FL-01** [ALL][M] Flutter SDK version pinned (FVM `.fvmrc` or equivalent) and identical in CI, developer machines and the release record; Dart SDK constraint pinned in `pubspec.yaml`.
- [ ] **FL-02** [ALL][M] `pubspec.lock`, `Podfile.lock` and Gradle lockfiles committed; CI uses `flutter pub get --enforce-lockfile`.
- [ ] **FL-03** [ALL][M] Release builds use `--obfuscate --split-debug-info=<dir>`; symbol files archived per build for crash symbolication and never shipped.
- [ ] **FL-04** [ALL][M] Release builds strip debug logging: `kReleaseMode` guards, `assert`-only diagnostics, logger level set at build time, no `print` of request/response bodies.
- [ ] **FL-05** [ALL][M] Build flavors / dart-define per environment (dev, staging, prod) select the Firebase project; production config cannot be selected in a debug build.
- [ ] **FL-06** [ALL][M] Version name and build number are generated by CI from the release record; the "About" screen shows version, build, UDI and regulatory info.
- [ ] **FL-07** [ALL][M] Builds are reproducible from a tagged commit in CI only; no developer-machine release builds.
- [ ] **FL-08** [ALL][S] Android: R8/ProGuard enabled with keep rules reviewed; `shrinkResources`; no `debuggable` or `testOnly` flags in release manifests.
- [ ] **FL-09** [ALL][S] `flutter analyze` with strict rules (`strict-casts`, `strict-inference`, `strict-raw-types`) and zero warnings as a CI gate; `dart format` check.

## B. Secrets and configuration

- [ ] **FL-10** [ALL][M] No secrets in the app bundle. Firebase config (API key, project ID) is not secret, but **API keys are restricted** in Google Cloud Console to the exact iOS bundle IDs, Android package + SHA-256 and web referrers, and limited to Firebase APIs.
- [ ] **FL-11** [ALL][M] Third-party API keys (maps, LLM, SMS) are never in the client; calls go through Cloud Functions.
- [ ] **FL-12** [ALL][M] `google-services.json` / `GoogleService-Info.plist` per flavor; production files not committed if the repo is public or shared with contractors (or accepted as non-secret with key restrictions in place, documented).
- [ ] **FL-13** [ALL][M] Remote Config and feature flags cannot disable a safety control or change a clinical algorithm; the list of what flags may change is in the architecture document.

## C. Local data protection

- [ ] **FL-20** [ALL][M] Sensitive values (tokens, device keys, cached identifiers) stored via platform secure storage (Keychain with `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` or similar; Android Keystore-backed storage), never in `SharedPreferences`, plain files or `Hive`/`sqflite` without encryption.
- [ ] **FL-21** [ALL][M] Local database (sqflite/Drift/Isar/Hive/ObjectBox) is encrypted (SQLCipher or library-native encryption) with the key in Keystore/Keychain; justification if no local PHI cache exists at all (preferred).
- [ ] **FL-22** [ALL][M] Firestore offline persistence: decision recorded on whether to enable it; if enabled, cache size limited, cleared on sign-out, and the device-level encryption dependency (OS full-disk encryption) stated in the IFU.
- [ ] **FL-23** [ALL][M] Android `android:allowBackup="false"` and `fullBackupContent`/`dataExtractionRules` exclude app data; iOS files marked `NSFileProtectionComplete` and excluded from iCloud backup where they contain health data.
- [ ] **FL-24** [ALL][M] Sign-out and account deletion wipe local caches, secure storage, image caches (`cached_network_image`), temp directories and Firestore persistence.
- [ ] **FL-25** [ALL][M] Clipboard: copying of health values is deliberate (explicit button), clipboard cleared after a timeout where the platform allows; no sensitive data in clipboard by default.
- [ ] **FL-26** [ALL][S] Screenshots and screen recording of PHI screens blocked or blurred (`FLAG_SECURE` on Android; obscuring view on iOS app switcher; `secure` content on web where feasible).
- [ ] **FL-27** [ALL][S] Keyboard: `enableSuggestions: false`, `autocorrect: false` and non-personalised keyboard for sensitive fields to avoid third-party keyboard learning.

## D. Session, lock and authentication UX

- [ ] **FL-30** [ALL][M] App lock after inactivity (configurable timeout, default short for clinician apps) with biometric or PIN re-authentication (`local_auth`) backed by a server-side session check, not just a UI gate.
- [ ] **FL-31** [ALL][M] Biometric fallback and failure paths defined; biometric enrolment change invalidates the key (`setInvalidatedByBiometricEnrollment` / `biometryCurrentSet`).
- [ ] **FL-32** [ALL][M] Background/foreground transitions hide PHI (privacy screen) and re-check session validity.
- [ ] **FL-33** [ALL][M] Multiple accounts on one device handled explicitly (family devices): data of a previous user never visible to the next.
- [ ] **FL-34** [ALL][S] Deep links and push taps that open PHI require authentication first; the intended route is preserved after login.

## E. Network security

- [ ] **FL-40** [ALL][M] TLS only: iOS App Transport Security without exceptions; Android `usesCleartextTraffic="false"` and a Network Security Config; web build enforces HTTPS and HSTS.
- [ ] **FL-41** [ALL][S] Certificate or public-key pinning for your own backends (Cloud Functions custom domain, FHIR server) with a rotation plan; pinning Firebase/Google endpoints is not recommended, so document the compensating controls (App Check, TLS, platform trust store).
- [ ] **FL-42** [ALL][M] All custom HTTP calls go through one client with timeouts, retry policy, error mapping and no logging of bodies; no `badCertificateCallback` that returns `true`.
- [ ] **FL-43** [ALL][M] WebViews only when needed; JavaScript disabled unless required, file access disabled, allowlist of URLs, no PHI passed via URL, external links open in the system browser.
- [ ] **FL-44** [ALL][M] Deep link verification: Android App Links with `assetlinks.json`, iOS Universal Links with `apple-app-site-association`; custom URL schemes not used for anything security-relevant; all parameters validated.

## F. Device integrity and platform

- [ ] **FL-50** [ALL][M] Root/jailbreak, debugger, hook and emulator detection (e.g. freeRASP or equivalent) with a defined response that matches the risk analysis (warn, degrade, block); the response is tested and stated in the IFU.
- [ ] **FL-51** [ALL][M] Minimum OS versions set from the security support matrix; devices below are blocked with a clear message; policy reviewed yearly.
- [ ] **FL-52** [ALL][M] Permissions are minimal and requested just-in-time with rationale screens; `Info.plist` usage strings and Android `<uses-permission>` list reviewed against the data-safety declaration.
- [ ] **FL-53** [ALL][M] Notifications: payloads carry no PHI; lock-screen preview content is generic; notification channels/categories allow users to control them; critical alerts (iOS) or high-priority channels justified in the risk file.
- [ ] **FL-54** [ALL][M] Background execution (sync, BLE, reminders) handles OS termination, Doze, battery optimisation and App Refresh being off; the user is told when background behaviour is degraded.
- [ ] **FL-55** [ALL][M] Time handling: all timestamps stored in UTC with time-zone offset where clinically relevant, displayed in device time zone, tested across DST and travel; device clock drift detected against server time for dose/schedule features.
- [ ] **FL-56** [ALL][S] Device-specific issues in the supported matrix tested: notched screens, foldables, tablets, split screen, font scaling to 200 %, dark mode, low-memory kills.

## G. Correctness of clinical data handling in the UI

- [ ] **FL-60** [ALL][M] Numeric input uses decimal-safe types (`decimal` package or integer minor units), never `double` for doses, weights or lab values with clinical thresholds; parsing honours locale decimal separators.
- [ ] **FL-61** [ALL][M] Units displayed with every value, user-selectable where appropriate (mg/dL vs mmol/L, kg vs lb), stored canonically (UCUM) with conversion tested to reference values.
- [ ] **FL-62** [ALL][M] Range checks and plausibility limits on inputs, with confirmation for out-of-range values and hard limits for impossible ones; limits reviewed by a clinician.
- [ ] **FL-63** [ALL][M] Stale or offline data is visibly marked (timestamp, "last synced"); never shown with the same visual weight as fresh data.
- [ ] **FL-64** [ALL][M] Patient identity shown on every clinical screen (name/pseudonym + second identifier) to prevent wrong-patient errors; patient switch requires a deliberate action.
- [ ] **FL-65** [ALL][M] Destructive or clinically significant actions (delete record, confirm dose, send to clinician) require confirmation and are undoable or logged.
- [ ] **FL-66** [ALL][M] Rounding, truncation and display precision rules documented and tested against the algorithm specification.
- [ ] **FL-67** [ALL][M] Error states are explicit: no silent fallbacks to default values; failure to load shows an error, not zero.
- [ ] **FL-68** [ALL][S] Charts have axes, units, legends and accessible alternatives (table or summary) and never interpolate across gaps without indication.

## H. Code quality and architecture

- [ ] **FL-70** [ALL][M] Layered architecture (presentation / domain / data) with the clinical logic in pure Dart packages that are unit-testable without Flutter or Firebase.
- [ ] **FL-71** [ALL][M] State management is deterministic and testable; side effects isolated; no business logic in widgets.
- [ ] **FL-72** [ALL][M] Error handling strategy: typed failures, global error handler (`FlutterError.onError`, `PlatformDispatcher.onError`) reporting without PHI, user-facing messages reviewed.
- [ ] **FL-73** [ALL][M] Platform channels / FFI reviewed for input validation and memory safety; native code is in the SBOM.
- [ ] **FL-74** [ALL][S] Dependency count minimised; each package in `pubspec.yaml` has an owner and a reason in the SOUP register.
- [ ] **FL-75** [ALL][S] Code review checklist includes security, accessibility, localisation and 62304 traceability (requirement ID in PR).

## I. Flutter web specifics (if shipped)

- [ ] **FL-80** [ALL][M] Content Security Policy, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` headers configured on Firebase Hosting; CanvasKit/WASM assets served from your origin or an allowlisted CDN.
- [ ] **FL-81** [ALL][M] Firebase Auth persistence set appropriately for shared clinical workstations (session persistence, not local) and idle logout implemented.
- [ ] **FL-82** [ALL][M] Semantics enabled and tested with screen readers in the browser; keyboard navigation works for all flows.
- [ ] **FL-83** [ALL][S] Browser support matrix and auto-update behaviour documented; service worker caching excludes PHI responses.
